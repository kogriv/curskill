# Что умеет curskill

Английский — источник правды: [capabilities.md](capabilities.md).

Это каталог. [SKILL.ru.md](SKILL.ru.md) — порядок, по которому агент
ведёт стенд. [reference.ru.md](reference.ru.md) — отказы, якоря и
договор доктора. Пути ниже — от корня скилла. `scripts/stand.sh`
находит `automation/cursor-stand.sh`.

Стенд — один экран X11, по умолчанию `:105`, и один профиль Cursor.
Новый агент — новая вкладка, не новый X-сервер. Успех новой сессии
Remote Control — строка `local-rc`: запрошенная папка на этом диске и
воркер `@ этот хост`. Снимок с надписью «This Computer» этой строкой
не является.

`park`, `ensure` и `down` останавливают Cursor стенда. На этом стенде
это останавливает и воркер чата, который здесь выполняется.

## Команды стенда

### doctor

`scripts/doctor.sh` печатает проверку хоста: скрипт, команды, экран,
бинарники, есть ли окно Agents, логин да или нет, строки якорей,
занят ли стенд, прокси портом или «не задан», число воркеров и мышь
стола. Код 0 значит, что клик разрешён. Занятый стенд не получает
`handoff --dry-run`. Расхождение `CURSOR_STAND_UI_CALIBRATED` с пакетом
— предупреждение, не координата клика. Команда не печатает адрес
логина, URL прокси и командную строку воркера и не поднимает экран.

### pick-display

`scripts/pick-display.sh` и `scripts/stand.sh pick-display` печатают,
какой рендер возьмёт `CURSOR_STAND_X`: NVIDIA Xorg, Xvfb или отказ.
`auto` берёт видеокарту только когда есть драйвер, конфиг и sudo без
пароля. `xorg` отказывается, а не прячется на Xvfb. AMD, Intel и
Wayland не сделаны. Команда X-сервер не запускает.

### status

`scripts/stand.sh status` печатает экран стенда, профиль, живы ли экран
и окно Cursor Agents, слушает ли VNC, и строку логина профиля. Кликов
нет. Строку логина в ответ человеку не переносят.

### up

`scripts/stand.sh up` поднимает стенд: X-сервер, оконный менеджер,
Cursor Agents в `0,0` × `1920×1080` и x11vnc на localhost. Пути папки
в аргументах нет. Живой `:105` второй раз не запускается. Без окна
Agents команда не заканчивается успехом. Сессию она не создаёт.

### workers

`scripts/stand.sh workers` открывает вкладки `local-rc` этой машины, у
чьих папок ещё нет воркера, чтобы воркер мог стартовать. Вкладку, чей
ход уже идёт, не переключает. Новую сессию не создаёт и `agent worker`
не запускает.

### ensure

`scripts/stand.sh ensure` делает то, что делает таймер: `up`, если
стенд не целый, затем `workers`. Руками — только когда человек
попросил. Может остановить Cursor стенда, когда считает стенд свободным.
Это не способ перечитать MCP и не способ применить правку лаунчера.

### shot

`scripts/stand.sh shot` пишет PNG экрана стенда в `var/shots/` профиля.
Кликов нет. Снимок с адресом логина, URL прокси или паролем VNC в git
не кладётся.

### handoff

`scripts/stand.sh handoff -w /ABS/PROJECT -n имя --then 'задача'`
открывает новую вкладку Agents на эту папку, шлёт короткое первое
сообщение, ждёт конца этого хода, конвертирует футер из This Computer
в Self-Hosted Worker и затем шлёт задачу. Успех — блок «куда смотреть»:
bc-id, `https://cursor.com/agents/<bc-id>`, класс `local-rc`, папка,
воркер `@ этот хост`, имя если его просили, экран стенда, VNC на
localhost, мышь стола и то, что чужие вкладки не переименовывались.
Пароля VNC, URL прокси и адреса логина в блоке нет.

`--no-convert` оставляет локальный чат для позднего `convert`.
`--dry-run` проходит якоря и не жмёт Return. Папка — абсолютный
существующий каталог. Слэш `/remote-control` не используется: на
сборках, где стенд измеряли, он поднимает сессию Environment. `agent
worker start` эту вкладку не открывает. Замер 26.11.2026: команда вышла
без аутентификации и вкладку профиля стенда не создала.

### convert

`scripts/stand.sh convert --id <uuid|bc-|имя>` делает ту же конвертацию
футера на вкладке, которая уже открыта. `--dry-run` меню не нажимает.
Закрытую вкладку через New agent не ищет. Итоговый класс `environment`
— стоп, а не второй круг тех же кликов.

### rename

`scripts/stand.sh rename --id bc-… имя` переименовывает эту строку
сайдбара. `--from` и `--current` выбирают строку по видимому имени или
по выделенной вкладке. Клик есть только когда подсвеченная строка —
эта сессия. Чужие вкладки не переименовываются.

### focus

`scripts/stand.sh focus --id bc-…` выделяет вкладку этой сессии. Сессию
не создаёт и текст не отправляет.

### archive

`scripts/stand.sh archive --id bc-…` архивирует одну строку сайдбара,
которую видит `resolve`. Ход со `status=1` — отказ. Пустой список
защиты — отказ до клика. Пункт меню — Archive, не Archive All Below.
Защищённые id и имя — отказ.

### discard

`scripts/stand.sh discard --id <uuid>` убирает один локальный черновик
без строки в базе профиля. Строку, которую видит `resolve`, архивируют
или конвертируют, не Discard. Команда отказывается, когда на экране
слово Stop, когда id или имя в списке защиты и когда правый клик попал
бы в другую вкладку. Если меню показывает Archive, потому что черновик
уже ответил, нажимается этот один пункт Archive. Archive All Below не
используется. Нет пункта меню — отказ, соседняя точка не кликается.

### composer-send

`scripts/stand.sh composer-send --id bc-… 'текст'` вставляет текст в
поле этой вкладки и жмёт Return, затем ждёт, что ход этой вкладки
начался. Поле ищется на снимке. Диалог Move agent отменяет отправку.
Чужая вкладка ради клика не выделяется. `agent resume` заменой не
является.

### wait-worker

`scripts/stand.sh wait-worker /ABS/PROJECT` ждёт, пока частный воркер
этой папки запущен. Командная строка воркера не печатается.

### mcp

Customize → MCPs в окне стенда. Окно Agents читает проектный
`.cursor/mcp.json`. Воркер вкладки `local-rc` при старте читает
`~/.cursor/mcp.json` и файл папки не читает. Уже запущенный воркер
пользовательский файл не перечитывает. Новая вкладка той же папки идёт
в тот же воркер. Тумблеры Settings → Agents не кликаются. `agent mcp`
не меняется.

#### list

`scripts/stand.sh mcp list` печатает серверы панели MCPs и статус
`enabled`, `disabled` или `error`. Тумблеры не переключает.

#### find

`scripts/stand.sh mcp find NAME` печатает строку этого сервера или
выходит с кодом 1, когда панели его нет. Строка здесь не доказывает,
что вкладка `local-rc` может вызвать сервер.

#### enable

`scripts/stand.sh mcp enable NAME` включает тумблер источника этого
сервера. Если тумблер уже включён, повтор ничего не меняет. Форму
New MCP Server не заполняет.

#### disable

`scripts/stand.sh mcp disable NAME` выключает этот тумблер источника.

#### add

`scripts/stand.sh mcp add -w /ABS -n NAME --command /path` пишет файл
папки для окна Agents и затем включает тумблер. `scripts/stand.sh mcp
add --user -n NAME --command /path` пишет пользовательский файл: его
прогреет новый воркер. Секреты в argv не передаются. Одного файла папки
вкладке мало.

#### ready

`scripts/stand.sh mcp ready NAME --id bc-…` проверяет одну открытую
вкладку `local-rc`. Имя должно быть в пользовательском
`~/.cursor/mcp.json`, а кэш воркера этой папки уже должен его содержать.
Панель не должна говорить disabled. Во вкладку уходит одно сообщение.
Успех — токен инструмента или ответ `MCP-SEEN`. `MCP-MISSING` внутри
пузыря просьбы не считается. Одного файла папки мало: команда
отказывается до сообщения.

### settings

`scripts/stand.sh settings agents` открывает Settings → Agents,
прокручивает страницу и печатает обязательные строки: Remote Control,
self-hosted workers, очередь новых сообщений, Run Mode, Read Access,
защита удаления, защита файлов вне папки, Web Search, ожидание MCP, и
ниже Computer Use и Legacy Terminal. Ничего не переключает. Не кликает
Cloud Agents, Docs, Unregister All, Log Out, Manage Environment и
Build on App.

### park

`scripts/stand.sh park` останавливает Cursor стенда и его воркеры.
X-сервер и VNC остаются. Cursor на столе владельца не останавливает.
На стенде, чей воркер — этот чат, ход обрывается вместе с процессом.

### down

`scripts/stand.sh down` делает `park` и затем останавливает x11vnc
экрана стенда. X-сервер остаётся.

### down-display

`scripts/stand.sh down-display` останавливает X-сервер стенда и только
этот экран. Пока Cursor стенда ещё работает, команда отказывается.
X-сервер стола владельца не останавливает.

## Чтение профиля

`scripts/glass.sh` читает профиль стенда. Эти команды не кликают.

### inventory

`scripts/glass.sh inventory` печатает неархивные строки: id, имя,
папка, класс (`local-rc`, `environment`, `private-incomplete`, `other`),
идёт ли ход, воркер. Выделенный uuid без строки базы — `local-draft`.
`agent ls` источником не является.

### selected

`scripts/glass.sh selected` печатает id выделенной сессии.

### show

`scripts/glass.sh show bc-…` печатает класс, папку, воркер и состояние
архива этого id.

### newest

`scripts/glass.sh newest /ABS/PROJECT [since_ms]` печатает новейшую
строку `local-rc` этой папки. Строка `environment` совпадением не
является.

### created-since

`scripts/glass.sh created-since <epoch_ms>` перечисляет сессии, созданные
после этого времени.

### handoff-ok

`scripts/glass.sh handoff-ok /ABS/PROJECT [since_ms [uuid]]` выходит с
кодом 0, когда строка этой папки — `local-rc` с воркером на этом хосте.
Строка, которая ещё `environment`, пока `convert` ждёт, сама по себе
отказом не является.

### mine

`scripts/glass.sh mine "$(hostname)"` перечисляет строки `local-rc` и
локальные строки этой машины, с колонкой хода.

### busy

`scripts/glass.sh busy "$(hostname)"` перечисляет строки, чей ход идёт,
и выделенный локальный черновик без строки базы.

## Чего эти команды не делают

Они не оборачивают терминальный `agent`: режим print, persist, resume,
worktree, sandbox, модели, правила и плагины. Они не запускают `agent
worker` и не ведут пул. Они не держат второй список одобрения MCP для
CLI. Они не создают Cloud Agent. Они не открывают файлы в редакторе
(`--goto`, `--diff`, `--merge`). Они не редактируют Settings → Agents.
Они не открывают VNC дальше localhost.

Остальные глаголы `glass_agents.py` (`anchor`, `reply-has`, `mcp-list`
и прочие) — это как скрипт стенда читает снимок. Второй способ вести
окно из чата из них не делается.
