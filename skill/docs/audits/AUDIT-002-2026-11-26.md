## Чем скилл отличается от трёх способов запустить агента

У Cursor три разных способа, и это не одна сессия. Сводка уже стоит в
`README.ru.md` и в `skill/reference.ru.md`. Здесь она расписана так,
как её видно на этой машине в день сверки.

Cloud Agents. Модель и инструменты работают в облаке Cursor, на чужой
виртуальной машине. Плодить такие сессии умеют API и MCP-сервер
`cursor-cloud`. Скилл их не создаёт. В `SKILL.md` уже стоит запрет
подменять вкладку Agents Window командой `agent create-chat`.

Терминальный CLI `agent`. Процесс на этой машине, со своим хранилищем
чатов `~/.cursor/chats/.../store.db`. Это не вкладка Agents Window.
История этого хранилища во вкладку не переносится. Путь к `store.db`
можно отдать новой десктопной сессии как бриф, и только так.

Agents Window и Remote Control. Чат — десктопное окно Cursor. Инструменты
выполняет свой воркер этой машины, из профиля стенда. Штатного вызова
«открой новую вкладку и включи Remote Control на эту папку» нет. Слэш
`/remote-control` на сборках, где стенд измеряли, поднимал Environment:
облачную среду с `workspaceRootPath=/workspace`, а не воркер на диске
этой машины. Успех стенда — строка в базе профиля: класс `local-rc`,
запрошенная папка, воркер `@ этот хост`.

Скилл держит второе окно X11, чтобы эти клики не двигали мышь стола
владельца. Один компьютер — один стенд. Новый агент — новая вкладка, не
новый X-сервер.

Десктопный Cursor стенда — пакет 3.30.14. `cursor --help` этой сборки

Команды установленного `agent`, верхний уровень справки:

| команда | что делает по справке этой сборки |
|---|---|
| `agent [prompt]` | интерактивный агент в терминале |
| `agent -p` / `--print` | тот же агент без вопросов в терминале, ответ в stdout; форматы `text`, `json`, `stream-json` |
| `agent persist` | сессия, которая переживает обрыв терминала и SSH; подкоманды `list`, `attach`, `stop` |
| `agent ls`, `agent resume`, `--continue`, `--resume` | продолжение чатов CLI |
| `agent create-chat` | пустой чат CLI и его идентификатор |
| `agent worker` | воркер Self-Hosted / My Machines: исходящее соединение с Cursor, инструменты на этой машине. Без `--pool` это личная машина, несколько агентов сразу. С `--pool` это командный пул, один агент на воркер, нужен план Enterprise и ключ сервисного аккаунта |
| `agent mcp` | `login`, `list`, `list-tools`, `enable`, `disable` для серверов из `mcp.json`. Это список одобрения CLI |

| `agent models`, `--model`, `--mode`, `--plan` | модель и режим plan/ask |
| `--sandbox`, `--force`, `--yolo`, `--auto-review` | песочница и разрешение команд |
| `--workspace`, `--add-dir`, `-w` / `--worktree` | папка, дополнительный корень, отдельное git-дерево |
| `agent plugin` | плагины и их каталоги |
| `agent generate-rule` | интерактивное правило |
| `agent update` | обновить сам CLI |
| `agent acp` | скрытый режим ACP-сервера |

Справка Cursor на сайте в день сверки описывает My Machines теми же
словами, что и Remote Control: `agent worker start` в каталоге

Agents. Цикл агента при этом остаётся в облаке, а файлы и терминал
выполняются на машине. Это описание продукта. Оно не является замером
стенда. На измеренных сборках скилла клик по чипу «Run on» и слэш
`/remote-control` давали Environment, а не `local-rc`. Пока замер
BL-067 не записан, эти два описания стоят рядом и не отменяют друг
друга.

## Пункты

### BL-067. Замер границы со справкой CLI

Наблюдение. Справка продукта и замер стенда расходятся в словах.
Справка говорит: Remote Control — это `agent worker start` и выбор
машины. Скилл говорит: слэш и чип «Run on» на измеренных сборках
поднимают Environment. Последний живой handoff 26.11.2026, 06:27 (+07)
снова дал `local-rc` кликами футера, на папке без GitHub-remote, за
10 секунд. Это не ответ на вопрос, даёт ли `agent worker start` ту же
папку без вкладки.

Развитие. Один замер на текущем десктопном Cursor и на той сборке CLI,
которая будет установлена в момент замера. Замер записывает команды,
версии, класс, `workspaceRootPath`, имя воркера и появилась ли вкладка
в профиле стенда. Новые клики по чипу папки до этой записи не
добавляются. `agent update` и перезапуск стенда в этот замер не входят,
пока человек их отдельно не попросил: этот чат сам работает воркером
стенда.

### BL-068. Учёт вкладок, которых нет в CLI

Наблюдение. `mine`, `show` и `busy` уже читают базу профиля стенда.
Они покрывают `local-rc`, локальные строки и флаг «ход идёт». Отдельной
команды, которая за один вызов печатает все четыре вида сразу, нет:
`local-rc`, `environment`, `private-incomplete`, локальный черновик без
строки `cloudAgentRepository`. CLI такой список по профилю стенда не
строит.

Развитие. Одна команда чтения, без кликов. Источник — база профиля и
тот способ, которым `mine` уже узнаёт локальный черновик. Вывод
`agent ls` источником не становится.

### BL-069. Убрать локальный черновик без строки в базе

Наблюдение. 25.11.2026 handoff в папку цикла был отменён на диалоге
«Move agent while working». В сайдбаре остался локальный черновик без

Развитие. Команда Discard для одного такого черновика. Отказ, если ход
идёт. Отказ, если сессия в списке защиты archive. Координаты с голоса
не подбирать. Живой черновик этой командой не трогать, пока человек
отдельно не попросил прогнать её на стенде.

### BL-070. Факт из базы не перепроверять обрезанным OCR

Наблюдение. 26.11.2026, 06:27 (+07) выделенная вкладка уже совпала с
нужным идентификатором, а имя в базе было известно. OCR прочитал
`instruction` как `instruc`. Проверка строки отказалась кликать.
Коммит `f33f2fd` принимает обрезанный хвост, если от слова осталось не
меньше половины, и повторное переименование прошло. Это частный допуск,
не опись всех проверок по снимку.

Развитие. Опись каждой проверки, которая сегодня читает снимок:
строка сайдбара при rename и archive, палитра, чип папки, надпись
Planning next moves, поле ввода, тумблеры MCP, страница Settings →
Agents. Для каждой строки описи — есть ли тот же факт в базе профиля.
Где факт уже есть, отказ из-за обрезанного слова в задачу на замену
не превращается сам: опись только называет такие места. Клик остаётся
там, где база клика не заменяет: попасть в кнопку на экране.

### BL-071. Второе сообщение в уже открытую вкладку

Наблюдение. `composer-send --id` фокусирует вкладку по базе, ищет поле
ввода по снимку и жмёт Return. Успех команды — координаты клика. Она не
проверяет, что ход начался у воркера этой вкладки. `agent --resume`
пишет в чат CLI, другое хранилище. Список сессий в облаке переживает
`park`. Продолжение Remote Control по тексту скилла требует открытой
вкладки этой папки на стенде.

Развитие. Отправка по идентификатору вкладки заканчивается проверкой,
что занят воркер этой вкладки, а не соседняя. Чат CLI и облачное
создание агента сюда не подключаются.

### BL-072. Доктор как договор перед кликом

Наблюдение. `scripts/doctor.sh` уже проверяет скрипт, команды, экран,
бинарники, логин glass, прокси по номеру порта, занятость стенда.
Последняя строка со словом `ЗАБЛОКИРОВАН` запрещает handoff. Свободный
стенд доктор кликает `handoff --dry-run`. Занятый не кликает. Это
набор проверок, а не записанный договор: какие поля печатаются всегда,
какой код возврата у готового стенда и у заблокированного, и что адрес
прокси и адрес почты в вывод не попадают.

Развитие. Поля и коды записаны в reference, и тест проверяет готовность
и блокировку на подставном выводе. В поля входят: экран, окно Agents,
логин есть или его нет (без адреса почты), якоря, занят ли стенд,
номер порта прокси если он задан, воркеры папок, мышь стола
(`unavailable` или координата). Доктор по-прежнему не печатает URL
прокси.

### BL-073. Якоря после обновления Cursor

Наблюдение. Якоря — слова на снимке в `glass_agents.py`. Неузнанный
якорь — отказ до Return. Калибровка в справке помечена `3.23`, живой
пакет — 3.30.14. Снимки прошлых отказов лежат в каталоге снимков
профиля и в git не входят. Юнит-тесты уже кормят `find_anchor` списками
слов с тех кадров. Отдельного набора, который прогоняется при смене
мажор.минор Cursor и говорит «якоря этой сборки не проверены», нет.
Живой ответ на смену UI — `doctor` и `handoff --dry-run` на свободном
стенде.

Развитие. Прогон юнит-тестов на сохранённых списках слов остаётся.
Рядом появляется явная проверка: версия, записанная как проверенная, и
версия пакета. Расхождение печатается доктором и не подменяется
координатами с голоса. Новый снимок в git не кладётся, если на нём
виден адрес почты или иной секрет.

### BL-074. Поведение, которое уже в коде и ждёт свободного запуска

Наблюдение. BL-055, BL-048, BL-049 и BL-056 закрыты тестами на
подставных файлах. На живом стенде они ещё не включались, потому что
для этого нужен `up` или `ensure`, а этот чат сам является воркером
этого Cursor.

Три следствия. Пароль VNC пишется в `$PROFILE/var/vnc.pass` с правами
`0600`, когда `up` поднимает x11vnc на свободном порту. Уже слушающий
x11vnc не трогается. Сгенерированный `xdg-open` переписывается при
`up`: в лог не попадает адрес целиком, флажка DevTools нет. Блок
лаунчера, который убирает `--api-key` из argv и отказывается при
несовпадении с уже заданным `CURSOR_API_KEY`, подхватывается при
`workers` или `ensure`. Уже запущенный воркер старый argv сохраняет до
следующего старта Cursor.

Развитие. Замер после свободного запуска, который человек попросил
отдельно. В замере есть: файл пароля существует и имеет права `0600`,
сам пароль не напечатан; новый `xdg-open` без URL в логе и без
DevTools; лаунчер содержит отказ при несовпадении ключа, значения ключа
в выводе нет. Пока стенд занят этим чатом, команду не запускать.

### BL-075. AMD, Intel и Wayland

Наблюдение. `README.ru.md` прямо говорит: не обещает и не проверялось
на AMD, Intel iGPU и Wayland. `CURSOR_STAND_X=auto` берёт NVIDIA, когда
есть драйвер, конфиг Xorg и passwordless sudo, иначе Xvfb. Ветка `xorg`
при отсутствии NVIDIA отказывает и на Xvfb молча не переходит.

Развитие. Задача заведена и стоит `blocked`, пока нет машины, где это
нужно измерить. Код под AMD, Intel и Wayland до такой машины не
пишется. На машине с NVIDIA и X11 текущий переключатель не ломается.

### BL-076. MCP виден открытой вкладке Remote Control

Наблюдение. `agent mcp enable` одобряет сервер для CLI. `cursor
--add-mcp` дописывает json в профиль. Скилл кликает Customize в профиле
стенда, потому что файл и список CLI не доказывают, что открытая
вкладка Remote Control сервер видит. В скилле уже расписан порядок:
найти, включить, при необходимости добавить в user json, затем
проверить отправкой в композер или готовностью namespace.

Развитие. Приёмка этого порядка становится проверкой на вкладке, а не
фактом записи json. Команда CLI остаётся командой CLI. Тумблеры
Settings → Agents эта задача не переключает.

Развитие. Вывод команды — устойчивая запись «имя, включено или

читать список отказов в скрипте и фикстуру слов. Живую страницу настроек
ради этого текста не открывать.

### BL-078. После handoff понятно, куда смотреть

Наблюдение. Успех handoff уже требует класс, папку, воркер, новый
идентификатор, имя если его просили, неподвижную мышь стола и
нетронутые чужие вкладки. Ответ человеку по скиллу включает адрес

на этой машине 5916, только localhost) в этот ответ отдельной строкой
не собран. Пароль VNC в ответ не входит и входить не должен.

Развитие. Ответ команды и текст скилла собирают в одном месте: вкладка
на экране стенда, порт VNC на localhost, адрес сессии, класс, папка,
воркер. Отдельный продукт удалённого стола не делается. x11vnc остаётся
на localhost.

### BL-079. Список того, что скилл на себя не берёт

- Отдельный продукт удалённого стола. Просмотр — x11vnc на localhost,
