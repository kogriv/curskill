коммит `f33f2fd` на `main`. Разбор, из которого взяты пункты, —

Этот файл говорит, куда скилл развивается и чего он на себя не берёт.
Он не заменяет `SKILL.md`: агент при обычной работе со стендом читает
скилл. Этот файл он открывает, когда его просят менять скилл или
добавить команду.

## Зачем стенд остаётся

Человеку нужна вкладка Agents Window на этой машине: чат виден в
десктопном окне, инструменты выполняет воркер профиля стенда, папка —
каталог на диске этой машины, мышь стола владельца остаётся на месте.
Терминальный `agent` такую вкладку не открывает и базу профиля стенда
не читает. Облачный агент выполняет инструменты на чужой машине.
Пока замер BL-067 не записан, клики handoff остаются способом получить
класс `local-rc` на запрошенной папке.

## BL-067. Замер границы со справкой CLI

Справка Cursor называет Remote Control и `agent worker start` одним
устройством: воркер на машине, цикл агента в облаке, выбор машины в
cursor.com/agents или в окне Agents. Скилл на измеренных сборках видел
другое: слэш `/remote-control` и чип «Run on» у нового чата дают
Environment, путь `/workspace`.

Задача — один записанный прогон, не новый кликер. В записи: версия
десктопного Cursor, версия `agent` (справку перечитать, установленная
26.11.2026 сборка `2026.09.15-d2fe57e` отстаёт от объявленной
`2026.11.22-e9042b2`), команда воркера и команда, которой открыт агент,
класс, `workspaceRootPath`, `privateWorkerDisplayName`, появилась ли
вкладка в профиле стенда. `agent update` сам по себе в прогон не
входит.

Если прогон даёт `local-rc` на запрошенной папке без вкладки стенда,
handoff остаётся для случая «нужна вкладка на этом экране». Если прогон
даёт Environment или другой путь, handoff остаётся способом получить
воркер на папке. До записи в бэклог чип не расширяется.

Стенд ради этого прогона из чата, который на нём работает, не
перезапускать.

## BL-068. Учёт вкладок, которых нет в CLI

`mine`, `show` и `busy` остаются. Появляется одна команда чтения,
которая печатает вместе:

- `local-rc`: идентификатор, имя, папка, воркер, идёт ли ход;
- `environment`: идентификатор, имя, `workspaceRootPath`;
- `private-incomplete`: те же поля, которые `classify` уже отличает;
- локальный черновик без строки `cloudAgentRepository`: как его видит
  сегодняшний `mine`, без клика.

`agent ls` в эту команду не подключается. Команда ничего не фокусирует
и не архивирует. Идентификаторы живых сессий в git не записываются.
Приёмка гоняется на временной базе.

## BL-069. Убрать локальный черновик без строки в базе

25.11.2026 после отмены handoff на диалоге «Move agent while working» в
сайдбаре остался черновик без строки в базе, под проектом временной
папки того прогона. Archive All Below запрещён. Discard с голоса, по
выдуманным координатам, запрещён.

Команда принимает один такой черновик. Она отказывается, если `busy`
показывает идущий ход. Она отказывается, если цель попадает в
`ARCHIVE_PROTECTED_IDS` или `ARCHIVE_PROTECTED_NAMES`. Она отказывается,
если якорь Discard на снимке не найден, и тогда не кликает соседнюю
точку. Живой черновик 25.11.2026 этой задачей не удаляется: удаление —
отдельная просьба человека уже после того, как команда есть.

## BL-070. Факт из базы не перепроверять обрезанным OCR

Коммит `f33f2fd` починил один случай: слово `instruction`, прочитанное
как `instruc`, больше не блокирует rename, если выделенная вкладка уже
совпала с идентификатором и от слова осталось не меньше половины.
Остальные ворота по снимку тем коммитом не описаны.

Опись, которую задача кладёт в reference:

- строка сайдбара перед правым кликом rename;
- строка сайдбара перед правым кликом archive;
- подтверждение палитры Search Agents;
- чип папки слева от This Computer;
- надпись Planning next moves;
- поле ввода composer-send;
- тумблер MCP в Customize;
- тумблер и список на странице Settings → Agents.

Напротив каждого пункта — факт из базы, если он есть, или прямая фраза,
что база этого не знает и снимок остаётся. Замена проверки кодом в эту
задачу не входит: она кончается описью. Следующая правка ворот
открывается отдельной задачей уже по строке описи.

## BL-071. Второе сообщение в уже открытую вкладку

`composer-send --id` сегодня фокусирует вкладку, кликает поле, найденное
по снимку, вставляет текст и жмёт Return. Печать координат считается
концом команды.

Приёмка добавляет конец: после Return команда ждёт, что ход этой
вкладки начался. Признак хода — тот, которым `busy` уже пользуется для
этого идентификатора (`status` хода), и воркер в строке `show` остаётся
воркером этой папки. Чужая вкладка при этом не получает фокус вторым
разом. Диалог «Move agent while working» по-прежнему отменяет отправку.
`agent resume` и создание облачного агента в эту команду не
подставляются.

## BL-072. Доктор как договор перед кликом

`scripts/doctor.sh` остаётся единственной проверкой перед работой.
Задача записывает договор в `reference.md` и `reference.ru.md` и
проверяет его тестом на подставном выводе, без живого клика.

Поля, которые печатаются каждый прогон:

- хост и пользователь;
- найденный `cursor-stand.sh` и обязательные команды;
- скрипт экрана и выбранный `CURSOR_STAND_X`;
- бинарники, без которых стенд не жив;
- окно Agents на дисплее стенда: есть или нет;
- логин профиля стенда: да или нет, без адреса почты;
- якоря: проверены для записанной версии UI или нет;
- стенд занят или свободен;
- прокси: не задан, либо номер порта и слушает ли он; URL не печатается;
- воркеры папок этой машины: сколько, без ключей из cmdline;
- мышь стола: `unavailable` или координата.

Код возврата: 0, когда кликать можно; не 0, когда последняя строка
содержит `ЗАБЛОКИРОВАН` или когда отсутствует обязательная часть.
Занятый стенд по-прежнему не получает `handoff --dry-run`. Свободный
стенд при `CURSKILL_SETUP_DONE=1` его получает, как сейчас.

## BL-073. Якоря после обновления Cursor

Юнит-тесты на списках слов остаются источником «этот кадр якорь
находит». Задача добавляет сверку версии. `CURSOR_STAND_UI_CALIBRATED`
и версия, которую handoff записал как проверенную, сравниваются с
пакетом Cursor. Доктор печатает расхождение отдельной строкой. При
расхождении handoff на занятом стенде и так не кликает; на свободном
`--dry-run` остаётся способом заново записать проверенную версию.
Координата, сказанная в чате, расхождение не закрывает.

Снимки с адресом почты, паролем или URL прокси в репозиторий не
добавляются. В тест идёт список слов, как уже сделано для кадров
15:51 и 15:57 25.11.2026.

## BL-074. Поведение, которое уже в коде и ждёт свободного запуска

Код BL-055, BL-048, BL-049 и BL-056 на свободном запуске начинает
делать три вещи. Задача — замерить их и дописать итог в бэклог. Сам
запуск делается только по отдельной просьбе человека и только когда
`busy` не показывает ход этого чата.

Пароль VNC. Файл `$PROFILE/var/vnc.pass`, права `0600`. Пароль не
печатается и в git не кладётся. Если порт уже слушает, текущий x11vnc
не перезапускается: тогда в итоге так и пишется, что файл появится на
следующем свободном порте.

`xdg-open`. Новый файл после `up` пишет в лог факт вызова, без
аргументов URL, и не передаёт Chrome `--remote-debugging-port`.

Лаунчер воркера. В тексте блока есть отказ, когда `CURSOR_API_KEY` уже
задан и не совпадает с `--api-key`. Значения ключа в выводе замера нет.
Уже бегущий процесс до своего следующего старта этот блок не
подхватывает: в итоге пишется, какой процесс ещё старый.

## BL-075. AMD, Intel и Wayland

Статус `blocked`. Машины, на которой это нужно, в задаче нет. До её
появления ветка NVIDIA / Xvfb не расширяется. Когда машина есть,
приёмка — файл хоста, прогон `pick-display` и один `status` без
перехвата чужого монитора. Этот роадмап такую машину не назначает.

## BL-076. MCP виден открытой вкладке Remote Control

`agent mcp enable` и запись json остаются средствами CLI и профиля.
Задача стенда кончается на открытой вкладке `local-rc`: сервер, который
просили включить, виден этой вкладке. Признак — тот, который скилл уже
называет в разделе MCP: готовность namespace или проверка отправкой в
композер этой вкладки. Запись в `mcp.json` одна, без этой проверки,
приёмкой не считается.

Тумблеры Settings → Agents не переключаются. Сервер CLI, которым
человек пользуется в терминале, эта задача не включает и не выключает.

## BL-077. Settings → Agents остаётся чтением

Команда `settings agents` печатает устойчивые строки по именам,
которые уже обязательны: Remote Control и Connected, self-hosted
workers, очередь новых сообщений, Run Mode, Read Access, защита
удаления, защита файлов вне папки, Web Search, ожидание MCP, Computer
Use, Legacy Terminal. Значение — включено или выключено, либо текст
списка.

Клика нет по Cloud Agents, Docs, Unregister All, Log Out, Manage
Environment, Build on App, поиску настроек, поиску Customize и по
строке проекта в сайдбаре. Второй экран настроек не пишется. Тест не
открывает живую страницу: он проверяет список отказов и разбор
фикстуры.

## BL-078. После handoff понятно, куда смотреть

Успешный handoff печатает один блок:

- идентификатор вкладки и адрес `https://cursor.com/agents/<bc-id>`;
- класс `local-rc`;
- папка, она же `workspaceRootPath`;
- воркер, строка с путём и `@ хост`;
- имя, если его просили;
- экран стенда, значение `CURSOR_STAND_DISPLAY`;
- VNC на localhost и порт `CURSOR_STAND_VNC`;
- мышь стола: не сдвинулась или `unavailable`;
- чужие вкладки не переименовывались.

Пароль VNC, URL прокси и адрес почты в блоке отсутствуют. Отдельный
сервер удалённого стола, проброс порта наружу и второй протокол
просмотра не добавляются. x11vnc остаётся с `-localhost`.

## Чего скилл не делает

Этот список совпадает с разделом в `SKILL.md` и `SKILL.ru.md`. Задача
на совпадение — BL-079.

Скилл не оборачивает терминального агента. Сюда входят `agent -p` и
`--print`, `agent persist` (`list`, `attach`, `stop`), `agent ls`,
`agent resume`, `--continue`, `--resume`, флаги worktree (`-w`,
`--worktree-base`, `--skip-worktree-setup`), sandbox (`--sandbox`),
выбор модели (`--model`, `agent models`, `--list-models`), режим
plan/ask, `agent generate-rule`, `agent plugin`.

Скилл не запускает `agent worker` и не управляет пулом. Сюда входят
`--pool`, `--worker-dir` как замена handoff, `--label`,
`--labels-file`, `--management-addr`, `--idle-release-timeout`,
`--mint-github-token`, `--clone-git-repos`, `--sync-dashboard-secrets`,
`--on-session-start`, `--on-session-end`, `--identity-socket`.

Скилл не ведёт второй список MCP для CLI. `agent mcp login`, `list`,
`list-tools`, `enable` и `disable` остаются командами CLI. Доведение
сервера до вкладки стенда — BL-076, это другая проверка.

Скилл не создаёт Cloud Agent и не подменяет им вкладку. `agent
create-chat` остаётся запрещённой заменой handoff.

Скилл не открывает файлы в редакторе и не делает сравнение. Флаги
десктопного `cursor` `--goto`, `--diff`, `--merge`, `--add`, `--remove`,
`--wait` остаются у `cursor`. Флаг `--glass` по-прежнему только
открывает окно и сессию не создаёт.

Скилл не заводит второй редактор Settings → Agents и не кликает
тумблеры этой страницы. Чтение — BL-077.

Скилл не заводит отдельный продукт удалённого стола. Просмотр экрана
стенда — x11vnc на localhost, строка в ответе handoff — BL-078.
