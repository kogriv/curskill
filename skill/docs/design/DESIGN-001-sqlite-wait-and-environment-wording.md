# DESIGN-001. Потолок sqlite 60 с и итог, а не середина ожидания

Закрывает [GAP-001](../gaps/GAP-001-sqlite-ui-lag.md) и
[GAP-002](../gaps/GAP-002-environment-while-convert-waits.md).

## Ожидание имени и архива

`poll_stdout_eq` в `automation/cursor-stand.sh` вызывает команду каждые
`CURSOR_STAND_POLL_INTERVAL` (дефолт 0.5 с) и возвращается в тот же тик,
когда stdout равен ожидаемому. Потолок —
`CURSOR_STAND_SQLITE_UI_WAIT_SEC`, дефолт 60. Это тот же порядок, что
ожидание sqlite после Return (BL-007 в старом бэклоге), и он покрывает
оба ложных отказа 25.11.2026, где запись появлялась без второго клика
позже 5 с.

`glass_rename` и `archive` сидят на этом опросе. Пятисекундных циклов
`1..10` в скрипте не остаётся.

`glass_rename` получает bc-id вторым аргументом. Ждёт
`resolve --id`, не `resolve --current`: за минуту ожидания выделенная
вкладка может смениться. `handoff`, `convert` и `rename` этот id
передают. Код выхода handoff по-прежнему 0, если имя так и не встало:
сессия `local-rc` уже есть, повторный `rename` остаётся шагом скилла, но
только после этих 60 с.

Классификацию `environment` не трогаем. Промежуточная строка верная.
Меняется текст, по которому агент решает остановиться.

## Текст про Environment

В `SKILL.md` / `SKILL.ru.md` стоп — итоговый класс после возврата
`handoff` / `convert`. Строка `environment` и `/workspace`, пока
`convert-ok` ещё считает, стопом не является: не rename и не второй
handoff в эту минуту. В `reference.md` / `reference.ru.md` вместо «первых
секунд» — замер 25.11.2026: git-папка до 50 с, `/tmp` без remote на 8-й
секунде. Отказ — если на 90-й секунде класс всё ещё environment.

Потолок `convert-ok` остаётся 90 с. Код этого ожидания не меняется.
